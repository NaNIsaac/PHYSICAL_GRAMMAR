# 13. Validation Protocol and Benchmarks

## 1. Primary empirical question

> How much scientific Feature/Quantity semantics can be reconstructed from Entity grounding and a small generic constructor grammar before domain-specific physical knowledge is required?

This allows success **and failure** to be informative.

## 2. Reducibility scale

### G0 — Grammar-derived

Generic grammar + seed kinds suffice.

Examples: same-Entity density/specific families, part-whole fractions, relative differences, rate/magnitude compositions.

### G1 — Generic mathematics required

Needs established non-domain-specific mathematics: metric, measure, topology, tensor operations, integration, differentiation.

Examples: distance, area, volume, extent, many geometric/tensor constructions.

### G2 — Domain semantic seed required

One physical/chemical construction must be supplied, then generic grammar composes it.

Examples: Crossing semantics, heat-capacity process definition, stress/traction continuum seed, some work/potential constructions.

### G3 — Model/law dependent

Meaning/formula depends on a model or physical law and should not be treated as a semantic definition.

Examples: Newtonian `p=mv`, `F=ma`, kinetic-energy formula, constitutive equations.

### G4 — Grammar failure

Current grammar cannot naturally express the supplied scientific definition. Repeated G4 failures may justify a new reusable mechanism.

## 3. Freeze-before-test rule

The constructor list must be frozen before the hidden benchmark is inspected.

Otherwise the exercise only proves that the grammar can be retrofitted.

## 4. Corpus design

Target 50–100 terms across:

- mechanics;
- electromagnetism;
- thermodynamics;
- continuum mechanics;
- chemistry;
- radiation physics;
- metrology;
- acoustics/waves;
- spectroscopy;
- statistical/quantum physics later.

Already-discussed terms such as density, fraction, flux, stress should be **development/training examples**, not the main hidden test.

## 5. Adversarial sets

### Same dimension, different semantics

- mass density vs mass concentration;
- fraction vs efficiency vs relative change;
- frequency vs decay constant vs angular frequency after SI projection;
- pressure vs stress;
- energy vs torque.

### Same arithmetic skeleton, different Entity binding

Hold `Mass(X)/Volume(Y)` fixed:

- `X=Y` → density-like;
- `PartOf(X,Y)` → concentration-like;
- unrelated `X,Y` → well-formed quotient but no established kind necessarily.

### Same kind, different roles

Reference/subject reversal; source/target reversal; component/whole reversal.

## 6. Minimal-domain-knowledge test

Hide conventional names and physical formulas.

Give only annotated semantic slots, e.g.:

```text
numerator: Mass(A)
denominator: Volume(A)
```

Ask the system to derive the binding pattern/grammar expression.

Then test lexicalization separately.

This separates:

- semantic construction ability;
- scientific naming knowledge.

## 7. Bottom-up induction

Given grounded examples:

\[
Mass(A)/Volume(A),
Mass(B)/Volume(B),
Mass(C)/Volume(C)
\]

induce:

\[
\lambda e.Mass(e)/Volume(e).
\]

Given repeated part/whole examples, induce a constrained two-variable schema.

Anti-unification / inductive logic programming are promising existing methods; do not invent a new induction mathematics unless necessary.

## 8. Evaluation dimensions

### Compression

How many named terms are generated by how many seed kinds and constructor families?

### Derivability

Distribution across G0–G4.

### Semantic discrimination

Can the grammar distinguish adversarial terms that dimension/algebra collapse?

### Failure novelty

Does a new mechanism resolve many failures or only one lexical exception?

### Recoverability / projection cost

Which distinctions are lost at each projection?

## 9. Success criterion

The goal is not maximum derivability at any cost.

A good grammar should maximize reusable explanation while respecting:

> Preserve justified distinctions; do not invent unjustified ones.
